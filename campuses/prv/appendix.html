Darío's PRA APPENDIX

Placement, prerequisites, and readiness for PRV.

A placement and readiness gate for the Privacy campus, not a lecture course: it tests modular arithmetic, probability, reductions, and implementation discipline through the existing PRE guide (with a Spanish-language RSA talk as an alternate route), then checks readiness for FHE (lattices, rings, noise accounting), ZKP (statements, commitments, soundness), PQC (threat model, replacement assumptions), and MPC (corruption model, ideal functionalities) before pointing outward to LAT and COD for the underlying mathematics and to PLV/CTH for the verification and hardware tools those four guides consume.

PRE ✓ → {FHE, ZKP, PQC, MPC}
readiness(g) = prereqs(g) ∧ Module-0(g)
LAT, COD → math; PLV, CTH → tools

Each of the four privacy guides keeps its own Module 0 and prerequisite checks; this page only confirms a gate is satisfied and sends the arithmetic, coding, and verification questions back to LAT, COD, PLV, and CTH rather than re-deriving any of them here.

Capstones & exit criteria

A finished route ends in an artifact you can run and a statement you can defend.

Privacy route dossier

  1. Choose a concrete privacy functionality and threat model.
  2. Select the established crypto guide that owns it.
  3. Attach PRE and guide-readiness evidence.
  4. Map arithmetic, coding, information, language, and hardware dependencies as pointers only.

Diagnostic loop

  • Diagnose: pass the PRE placement check for modular arithmetic, probability, reductions, and implementation safety.
  • Map: route every failed check to its exact PRE unit and a verifiable exit criterion.
  • Verify readiness: pass the Module-0 check of each selected guide (FHE, ZKP, PQC, MPC) instead of re-deriving it here.
  • Bridge: confirm which foundation (LAT, COD) or tool (PLV, CTH) guide any remaining gap actually belongs to.

Minimum portfolio

  • A privacy-route contract naming one primitive, security goal, and implementation artifact.
  • A dated diagnostic with every gap routed to a PRE unit.
  • A dependency map from PRE checkpoints to exact crypto-guide entry modules.
  • A readiness defense — proof plus small implementation — for each selected guide.
  • A primitive-to-foundation ownership matrix with no copied lesson sequences.

Exit criteria

Bundle map
You can name the crypto guide that owns your chosen privacy primitive, and state the security goal and implementation artifact it needs, without this appendix re-deriving primitive content.
Placement & diagnostics
You have completed the PRE placement check — modular arithmetic, probability, reductions, and byte-level implementation safety — dated, with every gap logged.
Prerequisite map
For every failed PRE check, you can name the exact PRE unit and a verifiable exit criterion that closes it.
Guide readiness
You can pass the Module-0 readiness check of your selected guide: lattices, rings, and noise accounting for FHE; statements, commitments, and soundness for ZKP; threat model and replacement assumptions for PQC; or corruption model and ideal functionalities for MPC.
Cross-bundle bridges
You can point an arithmetic, coding, verification, or hardware question back to LAT, COD, PLV, or CTH instead of answering it inside this appendix.
Place in the sequence
Passing these checks routes you into the guide whose primitive you chose — FHE, ZKP, PQC, or MPC — not back into this placement page.
