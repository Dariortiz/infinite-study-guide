Darío's SYA APPENDIX

Placement, prerequisites, and readiness for SYS.

A placement and prerequisite gate for the Systems campus, not a lecture course: it tests state-machine, concurrency, and architecture literacy through the existing PRE guide and a Spanish-language mutual-exclusion lecture, then checks readiness for PLV (induction, interpreters, finite transition systems) and CTH (reductions, asymptotic analysis, concurrency, measurement hygiene) before pointing outward to the DLT, TEE, and E2E guides that own their own protocols and consume PLV's and CTH's tools without duplicating them.

PRE ✓ → guide readiness
readiness(PLV) = induction ∧ FSM ∧ types
readiness(CTH) = reductions ∧ concurrency ∧ measurement

Nothing here replaces PRE, PLV, or CTH; each row is a gate that must be satisfied before the corresponding guide's own material starts, and a failed gate routes back to the exact missing prerequisite rather than a rewritten lecture.

Capstones & exit criteria

A finished route ends in an artifact you can run and a statement you can defend.

Systems ownership map

  1. Choose a property such as agreement, confidentiality, or constant-time behavior.
  2. Name the guide that owns each protocol and primitive.
  3. Identify PLV proof/model tools and CTH assumptions.
  4. Record diagnostics and first modules without cloning existing crypto content.

Diagnostic loop

  • Diagnose: run PRE and the mutual-exclusion lecture; log every miss.
  • Repair: return to PRE's own modules for each missed prerequisite; nothing is re-taught here.
  • Verify: retake the specific exit test PRE attaches to that dependency.
  • Route: pass PLV or CTH readiness only once every dependency clears.

Minimum readiness portfolio

  • Systems route contract naming one protocol, one formal model, and one machine boundary.
  • Diagnostic evidence and remediation list from PRE and the ES concurrency lecture.
  • Prerequisite map with a verifiable exit test per missing dependency.
  • One checked PLV model and one measured CTH machine behavior.
  • Ownership map with no duplicated protocol or crypto modules.
