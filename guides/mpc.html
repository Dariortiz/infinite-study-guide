Darío's MPC MOOC

Compute the function. Reveal nothing else.

A personalized course built from Bar-Ilan’s winter schools, then extended with Simons, NIST threshold work, EMP, MP-SPDZ, FROST, and Real World MPC. The focus is several parties computing a function without seeing one another’s inputs. TEEs, chains, and ratchets are sibling guides; credentials and Privacy Pass sit here as specialized protocols.

f(x1,…,xn) → y
[s] = s1+…+sn
ViewA ≈ Sim(y, xA)

Ideal-world simulation is the security claim. Secret sharing, OT, garbling, MACs, and preprocessing are how you approximate that claim on a real network.

Choose your route

There is no single official MPC MOOC. This guide uses Bar-Ilan’s 2011, 2015, and 2022 winter schools as the spine, then adds current implementation and attack material. The 2011 lectures still state the feasibility theorems; treat 2015+ for how those theorems became software.

~14 hours

Protocol literate

Watch every core theory unit and one implementation track: either garbled circuits (EMP) or secret-shared arithmetic (MP-SPDZ). Enough to read papers and evaluate threat models.

~24 hours

Balanced builder

The recommended route: all core units plus EMP, MP-SPDZ MASCOT, and one FROST signing lab. Never let the implementation trail the theory by more than one module.

~46 hours

Cryptography deep dive

Complete every unit, including TinyOT internals, silent OT/VOLE, FSS, ORAM, credentials, quantum-resistant threshold remarks, and both capstones. Conference extras only afterward.

What the labels mean

corePart of the default conceptual route across definitions, constructions, and engineering.
theorySimulation, assumptions, secret sharing, OT, garbling, MACs, compilers, and protocol design.
buildCircuits, frameworks, preprocessing, benchmarks, signing ceremonies, or adversarial tests.
optionalA longer specialization, alternate proof, or extra implementation branch.
Prerequisites: discrete mathematics, probability, algorithms, modular arithmetic, and introductory cryptography (commitments, PRFs, public-key encryption). Python is enough for secret sharing and MP-SPDZ programs; C++ helps for EMP; Rust helps for FROST.
Stay in this guide: this guide is compute-with-others—simulation, OT, garbling, SPDZ, PSI/PIR/ORAM, threshold keys. A TEE quote is not MPC (guide 6). Consensus is guide 5. Signal/MLS is guide 7. FHE and SNARKs are composition, not missing lectures.
Model rule: “MPC” is not one protocol. Always name the adversary (semi-honest vs malicious, static vs adaptive), the corruption threshold (honest majority vs dishonest majority), the network (synchronous, rushing, abort), and whether security is standalone or universally composable. A fast demo under semi-honest 2PC does not imply a wallet-grade threshold signer.

MODULE 01

Secret sharing and honest-majority MPC

Reconstruct Shamir and additive sharing; evaluate addition locally and multiplication with interaction; and state BGW’s honest-majority information-theoretic feasibility.

Unconditionally Secure Multiparty Computation
Benny Pinkas · 1st BIU Winter School 2011 · BGW

Polynomial secret sharing, degree doubling on multiplication, reduction, and why t < n/2 (semi-honest) or t < n/3 (malicious, no broadcast extra) appears in the information-theoretic setting.

Build: implement (3,5) Shamir sharing over a small prime field. Reconstruct from every 3-subset; prove every 2-subset is uniform. Then multiply two shared values with a degree-reduction step on paper.
▶ YouTube
Efficient Secure Computation with an Honest Majority
Yuval Ishai · 1st BIU Winter School 2011

How honest-majority protocols become practical: packed sharing, player-elimination ideas, and the cost of moving from “possible” to “linear in circuit size.”

Checkpoint: contrast additive n-out-of-n sharing (dishonest majority possible, abort on dropout) with Shamir t-out-of-n (dropout tolerance, honest-majority needed for multiplication).

MODULE 09

Implementation attacks and deployment

Treat concurrency, MAC checks, nonce sampling, and parser edges as part of the protocol; and distinguish a paper theorem from a wallet or analytics deployment.

How Secure Are SPDZ Implementations?
Sabine Oechsner & Peter Scholl · Real World MPC 2025

A rushing MAC-check attack that breaks major implementations under concurrency. The paper is Rushing at SPDZ (IEEE S&P 2025). Proofs that ignore thread pools are not proofs of your binary.

Audit: in your MP-SPDZ run, document when the MAC check executes relative to opening and output. State whether two overlapping sessions could reuse state. You are looking for a race, not inventing a new cryptanalytic break.
▶ YouTube
Practical Key-Extraction Attacks in Leading MPC Wallets
Nikolaos Makriyannis · NIST MPTS 2023 · BitForge / GG18–GG20 / Lindell17

Key extraction from deployed threshold ECDSA with as little as one signature in the worst case. Pair with Lindell’s later “people are implementing my papers” talk in the extras.

Rule: never ship GG18/GG20-era wallet code because a 2018 ePrint exists. Prefer maintained libraries with patches for BitForge-class bugs, current proofs, and an explicit nonce/abort story.

Protocol map

First decide whether you need interactive joint computation at all. Then choose by adversary and threshold, then by circuit type, then by whether a specialized protocol (PSI, PIR, FROST, credentials) beats generic MPC.

When MPC is the wrong primitive

Use MPCSeveral parties hold inputs, will interact, and should learn only the agreed outputs (plus named leakage). Simulation against a specified adversary and threshold is the claim.
Use FHEOne evaluator should compute on ciphertexts without a round-trip per gate. Composition with MPC is real; substitution is not. See the FHE guide.
Use ZKA public verifier should accept a short argument that a witness exists. Proving that an MPC transcript was honest is composition. See the ZK guide.
Use the chainYou need fork choice, data availability, or light clients. Threshold wallets in this guide are FROST/DKG, not a consensus course. Guide 5.
Use a TEEThe product trusts attestation and an enclave TCB. That is guide 6. An SGX quote is not a simulated ideal functionality.
Use session cryptoRatchets, MLS groups, TLS transcripts. Guide 7. HPKE-as-KEM lives with PQC; Noise/Signal state machines do not belong here.

Which MPC family

Yao / GCConstant rounds, two parties, Boolean/CPU-like circuits. Semi-honest is straightforward (EMP-sh2pc); malicious needs authenticated garbling or cut-and-choose. Strong when comparison-heavy and the circuit is known.
GMWn parties, rounds ≈ circuit depth, OT per AND. Honest or dishonest majority variants exist. Attractive when you want Boolean sharing without a garbler/evaluator asymmetry.
BGW / honest majorityInformation-theoretic possible for arithmetic circuits when t is small enough. Dropout-friendly with Shamir. Wrong tool if any coalition of honest-minority parties must be tolerated.
SPDZ / MASCOT / TinyOTDishonest majority, abort security, authenticated shares, preprocessing triples. Default research/production family for general arithmetic with a malicious majority. Check MAC-check concurrency.
Mixed (ABY, …)Convert between arithmetic, Boolean, and Yao. Use when no single representation is cheap. Conversion cost is part of the protocol, not an implementation detail.
PSI / PIR / FSSDo not garble “the whole database” if a custom lookup protocol exists. Write the leakage (sizes, thresholds, intersections) explicitly; it is often the real privacy policy.
FROST / threshold sigsNot generic MPC. Schnorr/FROST is standardized (RFC 9591). Threshold ECDSA is a different, sharper nonce problem. DKG, refresh, and abort handling dominate production risk.
Credentials / Privacy Pass / OHTTPIssuance and showing of unlinkable tokens, or oblivious HTTP to a target. Specialized 2PC, not “compile the identity provider into MP-SPDZ.” Module 10 plus the RFC extras.
Common mistake: demonstrating a semi-honest two-party demo and calling the product “MPC-secure.” Name the engine, the corruption threshold, abort vs fairness, and the exact functionality—including leakage—before you compare it to FHE or ZK.

Capstones and study loop

Protocol capstone

  1. Implement Shamir sharing and reconstruction.
  2. Add Beaver multiplication over a toy field with a dealer-generated triple.
  3. Remove the dealer: generate one triple from OT or from MP-SPDZ preprocessing.
  4. Forge a share and show the MAC check catching it.
  5. Write the ideal functionality and the exact abort leakage.

Systems capstone

  1. Pick one: private comparison, PSI of emails, or 2-of-3 Schnorr signing.
  2. Implement it in EMP, MP-SPDZ, or FROST—not a from-scratch crypto primitive.
  3. Measure communication, rounds, and CPU under LAN and a simulated delay.
  4. Change the security model (semi-honest ↔ MASCOT, or 2-of-2 ↔ 2-of-3) and record what broke.
  5. Write the threat model a lawyer could read: who colludes, who aborts, what sizes leak.

Weekly cadence

  • Watch: pause before each simulation argument.
  • Derive: reconstruct one protocol round without notes.
  • Build: run the same function in a real engine.
  • Break: malformed shares, reused nonces, skipped checks.
  • Explain: adversary, threshold, abort, leakage—aloud, no slides.

Minimum portfolio

  • Shamir (t,n) demo.
  • Garbled-circuit comparison in EMP.
  • MP-SPDZ program under MASCOT.
  • FROST 2-of-3 signature verified externally.
  • One-page model comparison (Yao vs SPDZ vs FROST).

Exit criteria

Definitions
You can state the real/ideal paradigm, semi-honest vs malicious, honest vs dishonest majority, abort vs fairness, standalone vs UC, and why OT is complete for 2PC.
Constructions
You can trace Yao, GMW, BGW, TinyOT/SPDZ, and FROST at the level of rounds, algebraic objects, and the check that provides malicious security.
Implementation
You can run EMP or MP-SPDZ, generate and consume triples or garbled gates, measure cost, and explain why a passed test is not a UC proof.
Judgment
You can choose PSI vs generic MPC vs FHE vs ZK for a problem, and refuse to treat an unpatched threshold-ECDSA paper as a custody design.
