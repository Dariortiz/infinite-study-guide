Darío's PLV MOOC

Specify the machine, then prove the transition.

A non-centralized course assembled from Robert Harper's OPLSS lectures on operational semantics, Benjamin Pierce's Types and Programming Languages, Jon Pearce's SJSU CS152 interpreter sequence, Santosh Nagarakatte's Verified LLVM talk and the Cytron et al. SSA paper, Leslie Lamport's TLA+ course and Specifying Systems, Pierce's Software Foundations in Coq, and the CDCL/SMT pair of Vijay Ganesh and Nikolaj Bjørner. The order is deliberate: specify a language's semantics and type safety first, build the interpreter and IR that must satisfy it, then hand the result to model checking, proof assistants, and solvers as independent, stronger checks. DLT, TEE, and E2E keep their own protocols; this guide supplies the semantics, compiler, model-checking, and proof-assistant machinery used to verify them.

Choose your route

There's no single course that goes from operational semantics to SSA-based compilation to temporal-logic model checking to machine-checked proofs without switching frameworks per topic. Harper and Pierce set the semantics and type-safety spine; Nagarakatte and the Cytron SSA paper carry it into a verified IR; Lamport's TLA+ and Pierce's Software Foundations add model checking and proof assistants; Ganesh and Bjørner close with SAT/SMT.

EXP

Semantics explorer

Watch Harper's operational-semantics lectures and prove progress/preservation with Pierce, build one interpreter from Pearce's CS152 closures lecture, take the LTL/TLA+ model-checking pair, complete Pierce's Software Foundations Lecture 1, and close with Ganesh's CDCL talk and Bjørner's Z3 walkthrough.

18–24 h + reading
BLD

Verified builder

Carry one typed language from Harper's operational semantics through Nagarakatte's verified LLVM IR and Cytron-style SSA construction, model a protocol state machine with Lamport's TLA+ and TLC, then discharge one property with Bjørner's Z3.

45–65 h
DIP

Mechanization deep dive

Add Zdancewic's OPLSS SSA-compilation lecture and Clarkson's Coq pattern-matching material, then mechanize a substantial semantics theorem or protocol invariant in Coq to Pierce's Software Foundations standard, with no admitted goals.

80–110 h

Capstones & exit criteria

A finished route ends in an artifact you can run and a statement you can defend.

Implementation capstone

  1. Define a typed source language, write its small-step operational semantics, and prove progress and preservation.
  2. Build an interpreter with explicit environments and closures, then lower it to an SSA-form IR with dominance-frontier phi placement.
  3. Implement one optimization pass and state its semantic-preservation claim precisely.
  4. Validate the generated IR against a written contract such as LangRef, not just against tests passing.

Verification capstone

  1. Take a small state machine — a consensus rule, an attestation policy, or a session-ratchet step from a sibling systems guide — and specify it in TLA+.
  2. Check safety and liveness invariants with TLC and interpret one counterexample trace.
  3. Mechanize one invariant or theorem about the same system in Coq with no admitted goals.
  4. Encode a bounded version of the same property as an SMT query and discharge it with Z3.
  5. State which guarantee came from exhaustive model checking and which came from the solver — they are not interchangeable.

Weekly loop

  • Watch: separate the operational rule from the theorem it is used to prove.
  • Derive: reprove one progress/preservation case or one CDCL conflict-analysis step by hand.
  • Build: extend one interpreter, IR pass, TLA+ spec, Coq proof, or SMT encoding.
  • Explain: state exactly what guarantee one method gives that another method would not.

Minimum portfolio

  • A typed interpreter with a hand-written progress and preservation proof.
  • An SSA-form IR lowering with dominance-frontier phi placement, checked against Cytron et al.'s algorithm.
  • A TLA+ model of a small protocol with two TLC-checked invariants.
  • A Coq mechanization of one semantics theorem or protocol invariant with no admitted goals.
  • A CDCL trace or Z3 encoding that discharges a concrete program or protocol property.

Exit criteria

Programming-language semantics
You can write small-step operational-semantics rules for a typed expression language and prove progress and preservation for it.
Interpreters, IR, and compiler construction
You can implement an interpreter with environments and closures, lower it to an SSA-form IR using dominance-frontier phi placement, and state a semantic-preservation claim for one optimization pass.
Model checking
You can specify a state machine in TLA+, classify a property as safety or liveness, check it with TLC, and interpret a counterexample trace.
Proof assistants
You can mechanize a small-step relation or a protocol invariant in Coq with no admitted goals.
SAT and SMT
You can trace CDCL conflict analysis to a learned clause and use an SMT solver such as Z3 to discharge a concrete program or protocol property.
Place in the sequence
This guide supplies the semantics, compiler, model-checking, and proof-assistant machinery, not any protocol's own construction: consensus and settlement belong to DLT, hardware attestation to TEE, and session-ratchet messaging to E2E — verify their protocols with the tools built here, but look to those guides for what each protocol actually claims.

Curation policy

Scope: programming-language semantics, interpreters, compiler IR, model checking, proof assistants, and SAT/SMT — the verification machinery, not any protocol's own construction. Blockchain consensus and settlement are the DLT guide, hardware attestation is the TEE guide, and session-ratchet messaging is the E2E guide; this guide supplies the tools those guides call on to verify their own protocols. Named editions, official references, and primary papers only; no unfiltered channel archives.
