Prerequisites

Public-key encryption, DH/ECDH, signatures, AEAD, hashes, and HKDF. Comfort reading RFCs and Rust, Go, or Python. Complete the PQC guide before hybrid KEMs and PQXDH internals; complete MPC before threshold identity keys.

Stay in this guide: this guide owns session state machines—TLS 1.3 handshake and key schedule, HPKE as a protocol (not merely a KEM wrapper), Noise patterns, Signal (X3DH/PQXDH + Double Ratchet), identity/prekeys, and MLS. Hybrid KEM combiners and lattice/code primitives are guide 3. FHE, ZK, MPC, consensus, and TEEs stay in their own guides.
Threat-model rule: “encrypted” is not a claim. Name authentication vs confidentiality, forward secrecy vs post-compromise security, 0-RTT replay, transcript binding, identity vs prekey compromise, group membership, and what metadata still leaks (timing, size, graph).

Session architecture map

First decide whether you need a live authenticated channel, a one-shot encapsulation, a pairwise ratchet, or a group epoch. Then pick the protocol whose state machine matches that decision.

When session crypto is the wrong primitive

Use sessionsTwo or more parties need an authenticated, evolving channel: TLS, Noise, Signal, or MLS. Compromise of long-term keys should not decrypt the past (FS); healing after leak is a separate requirement (PCS).
Use FHEAn evaluator must compute on ciphertext without a session between data owners and the server that yields plaintext. See the FHE guide. TLS may still protect the ciphertext in transit.
Use ZKAnyone must verify a statement from public proof, not from a private channel. See the ZK guide.
Use PQCThe primitive itself must be quantum-safe (KEM, signature, hybrid combiner). This guide consumes those primitives inside HPKE, PQXDH, and hybrid TLS; it does not teach lattice math. See the PQC guide.
Use MPCSeveral organizations must jointly compute or hold a key without a single session endpoint becoming the oracle. See the MPC guide.
Use the chainYou need shared history, availability, and settlement among mutually distrustful writers—not a confidential pipe. See the chain guide.
Use a TEEYou need to isolate compute from a privileged host and attest a measurement. Attestation can authenticate a workload into TLS; it does not replace ratchets. See the TEE guide.

Which session shape

TLS 1.3Client–server on the public Internet, certificates or raw public keys, 1-RTT (and carefully constrained 0-RTT). Default for HTTPS, gRPC, and most APIs.
HPKEOne-shot or few-shot encapsulation with explicit modes and exporters. Building block for ECH, MLS, and privacy relays—not a full duplex ratchet by itself.
NoiseCustom two-party handshakes with a small pattern language (XX, IK, NK, …). WireGuard is the canonical production example.
Signal DRAsynchronous pairwise messaging with prekeys, FS, and PCS. Multi-device and groups need extra protocols (SESAME, or MLS).
MLSDynamically changing groups with a ratchet tree and epochs. Requires an authentication service and a delivery service outside the RFC.
Common mistake: enabling TLS 1.3 0-RTT or “just HPKE” for a chat app and calling it Signal. Replay, identity, prekeys, skipped message keys, and group membership are separate designs.

Capstones and study loop

Transport capstone

  1. Trace a real TLS 1.3 handshake to RFC 8446 message names.
  2. Draw the key schedule from (EC)DHE to application traffic secrets.
  3. Write a 0-RTT accept/deny list for your application.
  4. HPKE Seal/Open against an RFC 9180 test vector.
  5. Map one VPN or mesh product to a Noise pattern.

Messaging capstone

  1. Compute an X3DH (or PQXDH) shared secret from a prekey bundle.
  2. Run a double ratchet for ≥8 messages with one skip.
  3. State what identity-key vs prekey compromise enables.
  4. Create an MLS group, add/remove a member, and show epoch change.
  5. List remaining metadata leaks (server, size, timing, graph).

Weekly cadence

  • Watch: draw the state machine, not the logo.
  • Derive: one HKDF label or DH mix.
  • Build: a vector, a trace, or a toy ratchet.
  • Break: replay, skip, downgrade, or wrong info string.
  • Explain: FS vs PCS vs authentication.

Minimum portfolio

  • TLS 1.3 handshake diagram + key schedule.
  • 0-RTT policy memo.
  • HPKE interop against test vectors.
  • Noise pattern map for one product.
  • X3DH + Double Ratchet simulation.
  • MLS epoch add/remove notes.

Exit criteria

TLS and HPKE
You can explain 1-RTT vs 0-RTT, draw RFC 8446 §7.1, verify certificates as a policy, and use HPKE modes/info/AAD without treating HPKE as “just a KEM.”
Noise and messaging
You can read a Noise pattern, map WireGuard to IK, compute X3DH, step a double ratchet including skipped keys, and explain PQXDH’s extra secret.
Groups and deployment
You can describe MLS epochs and trees, name authentication vs delivery services, and place QUIC and PQ3 as session compositions rather than new primitives.

Conference extras

Deployment talks and adjacent protocols—not hidden prerequisites. Re-check RFCs before implementation; handshake greasing and PQ hybrids move.
