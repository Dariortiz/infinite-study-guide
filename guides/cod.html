Darío's COD MOOC

Add structured redundancy; survive noise.

A video-first spine built from Mary Wootters's Stanford Algebraic Coding Theory lectures and Adrish Banerjee's NPTEL/IIT Kanpur Coding Theory course, extended by Robert Gallager's MIT 6.451 lattice-coding lecture and Ram Zamir's São Paulo Coding School series, backed by Roth, Huffman–Pless, Richardson–Urbanke, and Zamir. The order moves from Shannon capacity and finite-block bounds through linear, cyclic/BCH/Reed–Solomon, and trellis codes to the sparse-graph LDPC/polar family and finally Euclidean lattice codes for modulation and shaping. The lattice-reduction and shortest-vector machinery behind that last module is LAT's job, not rebuilt here; McEliece, FRI, and erasure-coded data availability stay in the PQC, ZKP, and blockchain guides, which import this guide's coding theorems rather than re-deriving them.

A code's minimum distance sets how many errors it can correct; the parity-check matrix turns that into a syndrome computation that identifies the error without searching the whole space; Shannon's capacity bound says which rates make that correction possible at all as blocklength grows.

Choose your route

There's no single course that carries Hamming/Singleton bounds through linear and Reed–Solomon codes, Viterbi decoding, and belief propagation without changing conventions halfway through. Wootters's Stanford lectures and Banerjee's NPTEL course supply the algebraic and trellis spine; Gallager and Zamir extend it into Euclidean lattice codes without duplicating LAT's geometry.

Capstones & exit criteria

A finished route ends in an artifact you can run and a statement you can defend.

Decoder laboratory

  1. Choose one algebraic, one trellis, and one graph-based code at comparable rates.
  2. Implement encoding and decoding with reproducible channel simulations.
  3. Measure block and bit error rates with confidence intervals and complexity counters.
  4. Explain each observed waterfall, floor, or failure using distance, state, or graph structure.

One theorem, three applications

  1. Choose Reed–Solomon, Goppa, or erasure-code mathematics.
  2. Prove one central coding theorem and implement a toy decoder or reconstructor.
  3. Map its use to ZKP, PQC, or data availability through the existing guide.
  4. Separate ordinary decoding guarantees from cryptographic or adversarial assumptions.

Weekly loop

  • Watch: separate the combinatorial bound from the algorithmic decoder that approaches it.
  • Derive: reprove one bound, generator-polynomial, or density-evolution step by hand.
  • Build: implement one encoder/decoder pair with injected-error tests.
  • Explain: state which sibling guide imports this theorem and what it does not import.

Minimum portfolio

  • Finite-field linear-code toolkit reporting codewords, distances, syndromes, and duals.
  • BCH or Reed–Solomon encoder with a bounded-distance decoder.
  • Convolutional encoder plus Viterbi decoder tested over an AWGN channel.
  • LDPC belief-propagation or polar successive-cancellation decoder.
  • Nested-lattice code with shaping compared against uncoded QAM.

Exit criteria

Bounds and linear codes
You can derive the Hamming, Singleton, and Gilbert–Varshamov bounds, compute binary-symmetric-channel capacity, and build generator/parity-check matrices with syndrome decoding for a linear code.
Cyclic, BCH, and Reed–Solomon codes
You can construct a BCH generator polynomial from prescribed roots, encode and decode a Reed–Solomon code, and state the designed-distance guarantee each relies on.
Trellis and graph-based decoding
You can implement Viterbi decoding on a convolutional trellis and sum-product belief propagation on an LDPC Tanner graph, and diagnose a trapping-set or short-cycle failure.
Lattice codes for modulation
You can build a nested-lattice code with shaping and nearest-neighbor decoding, and explain shaping gain versus coding gain relative to uncoded QAM.
