Choose your route

Do not complete this appendix front-to-back by default. Start with the shared core, attempt the readiness checkpoint for your destination, and fill only the gaps that stop you.

~22 hours

Shared core

Take core units in Modules 0–8. You should be able to read pseudocode, manipulate modular equations, reason with probability, and explain encryption, authentication, and signatures. This is already enough for TRC, which builds its own cryptographic vocabulary from Module 0 up.

Math-heavy

FHE · ZK · PQC · MPC

Prioritize Modules 1–7. FHE/PQC need linear algebra and noisy modular systems; ZK needs fields and polynomials; MPC needs probability, simulation language, and circuits.

Systems-heavy

Chain · TEE · Session

Prioritize Modules 0–2 and 5–9. Chain adds distributed systems; TEE adds architecture/OS/cloud; Session adds networking and modern cryptographic APIs.

Placement rule: a checked video is not evidence of readiness. Each module ends in an artifact or derivation. If you can produce it without help and explain every symbol or system boundary, skip ahead.

Guide readiness map

Modules listed as “must” are assumed in the first serious technical module of that guide. “Helpful” modules can be learned just in time.

1 · TRCMust: 0 and 2. Helpful: 1 and 4. You can write tested Python, compute modular inverses and exponentiation, and reason about basic probability — this guide builds its own cryptographic vocabulary from scratch, so Module 6 is not required first.
2 · FHEMust: 0–6. Helpful: 7 and 9. You can multiply matrices and polynomials modulo q, track noise/error, estimate complexity, and write a small Python experiment.
3 · ZKPMust: 0–7. Helpful: 8. You can write relations and witnesses, interpolate over a finite field, use probability in soundness arguments, and distinguish proof from implementation.
4 · PQCMust: 0–7. Helpful: 8–9. You understand vectors, norms, modular arithmetic, probability distributions, KEM/signature interfaces, constant time, and C/Rust memory.
5 · MPCMust: 0–7. Helpful: 8. You can reason about random variables, finite-field shares, Boolean/arithmetic circuits, adversaries, reductions, and public-key encryption.
6 · DLTMust: 0–2, 4–8. Helpful: 3 and 9. You know hashes/signatures, graphs, asymptotics, network delay, state machines, fault models, and basic probability.
7 · TEEMust: 0, 6–9. Helpful: 1–5. You can read C/Rust, trace virtual memory and system calls, distinguish process/VM/container boundaries, and threat-model privileged software.
8 · E2EMust: 0–2 and 4–8. Helpful: 9. You understand DH, signatures, AEAD, KDFs, transcripts, TCP/UDP, PKI, replay, and protocol state machines.

Capstones and exit criteria

Choose the capstone matching your destination. Completing one cleanly is stronger evidence than watching all forty units.

Mathematical readiness

  1. Implement a prime field and polynomial interpolation.
  2. Sample vectors modulo q and compute three norms.
  3. State a security experiment with adversary and advantage.
  4. Analyze runtime in bit complexity, not only loop count.
  5. Write tests for identities, edge cases, and randomized properties.

Systems readiness

  1. Trace bytes from a network socket into a process and persisted state.
  2. Draw process/kernel/VM/container/cloud boundaries.
  3. Model a handshake or replicated service as a state machine.
  4. Add replay, crash, malicious peer, and privileged-host adversaries.
  5. Record build, dependency, protocol, and test-vector versions.

Cryptographic literacy

  1. Explain encryption vs authentication vs signatures.
  2. Use a library AEAD with unique nonces and AAD.
  3. Use DH + KDF without treating raw shared output as a key.
  4. State what IND-CPA, IND-CCA, and EUF-CMA protect.
  5. List metadata and side channels the primitive does not hide.

Exit decision

  • If symbols stop you: Modules 1–4.
  • If code stops you: Modules 0, 5, 7, 9.
  • If protocols blur together: Modules 6–8.
  • If only one advanced topic is unfamiliar: enter its guide and backfill just in time.
  • Do not delay the eight for optional completeness.

Minimum exit criteria

Definitions before intuition
You can define the sample space, algorithm input size, field/ring, adversary, security goal, and system boundary before making a performance or security claim.
Small derivation
You can compute modular inverses, multiply matrices, interpolate a polynomial, calculate a conditional probability, and analyze a simple algorithm without copying steps.
Small implementation
You can write tested Python, inspect C memory code, use Git, run a vector, parse bytes, and distinguish a toy implementation from production cryptography.
System placement
You can place the eight guides correctly: the classical toolbox, ciphertext compute, proofs, post-quantum primitives, multiparty compute, settlement, hardware-attested compute, and session/messaging state.

Curation policy

This is an appendix to—not a ninth member of—the eight-guide curriculum. It centralizes assumed foundations without forcing every learner through a second degree. Priority went to public university videos, free primary texts, executable exercises, and durable course homes. Calculus, abstract algebra, compilers, formal methods, and quantum physics are included only when a chosen deep route actually needs them.
